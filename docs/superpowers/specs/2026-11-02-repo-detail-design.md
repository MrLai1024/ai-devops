# 代码仓详情与 MR 详情设计方案

> 版本：v0.1
> 日期：2026-11-02
> 状态：已确认（待实现）
> 范围：代码仓外层列表、仓库详情（代码 / 合并请求 / 配置）、MR 详情页
> 关联：[AI DevOps 平台总体设计方案](2026-10-23-ai-devops-platform-design.md)

---

## 1. 背景与目标

### 1.1 背景

代码仓外层当前有「代码仓库 / 合并请求」两个 Tab；仓库卡片只提供打开与复制操作，合并请求通过抽屉查看。用户希望外层改为纯代码仓列表，点击仓库进入类似 GitHub 的仓库详情页，并只保留代码、合并请求、代码仓配置三个核心功能。

### 1.2 目标

1. 代码仓外层改为纯仓库列表。
2. 新增仓库详情页，包含代码、合并请求、配置三个 Tab。
3. 代码 Tab 支持文件树浏览与文件内容查看。
4. 合并请求 Tab 展示当前仓库的 MR；点击 MR 进入独立详情页。
5. MR 详情页展示标题、说明、关联需求、流水线结果和评论区，评论区包含代码评审内容。
6. 代码仓配置支持编辑并保存在浏览器内存中。

### 1.3 非目标

- 不支持手工新建合并请求。
- 不提供 Issues、Actions、Wiki、Release、Commit 历史等 GitHub 扩展功能。
- 不提供独立 Diff Tab；变更规模在 MR 头部展示，代码评审上下文由评论中的文件/行号/代码片段承载。
- 不支持在页面上新增代码评审评论；评审评论为预置演示数据，普通评论可新增。
- 不提供仓库归档或删除。
- 不做真实 Git 集成、语法高亮或分支文件差异。

## 2. 信息架构与路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `#/code` | 代码仓列表 | 纯仓库列表，无 Tab；侧栏「代码仓」高亮 |
| `#/code/<repoId>` | 仓库详情 | 侧栏保留，代码仓高亮；顶部返回列表；Tab：代码 / 合并请求 / 配置 |
| `#/code/<repoId>/mrs/<number>` | MR 详情 | 保留侧栏；返回仓库详情并停留在合并请求 Tab |

- MR 显示编号为 `!128`，URL 使用数字 `128`。
- 直接访问详情路由时，根据仓库所属项目同步项目上下文，保证侧栏项目正确。
- 仓库详情和 MR 详情本身均为正文页面，不使用抽屉；关联需求可打开需求详情抽屉。
- 返回仓库列表使用 `#/code`；从 MR 详情返回时回到对应仓库的合并请求 Tab。
- 仓库或 MR 不存在时展示未找到状态，并提供返回代码仓列表的入口。

---

## 3. 代码仓列表

- 页面标题「代码仓」，保留「打开 Gitea」按钮。
- 仓库卡片展示：仓库名、路径、语言、描述、可见性、最近提交、MR 与文档数量。
- 点击整张卡片进入仓库详情；「复制地址」保留为独立操作。
- 卡片可键盘聚焦并回车进入详情。
- 无仓库时展示空状态。

---

## 4. 仓库详情

### 4.1 头部

- 返回链接「← 返回代码仓」。
- 面包屑：项目名 / 仓库名。
- 仓库名、可见性标签、描述、路径、默认分支、最近提交摘要。
- 操作：复制克隆地址。
- Tab：代码 / 合并请求 / 配置；合并请求 Tab 显示数量。

### 4.2 代码 Tab

- 工具条：分支下拉框、最新提交 hash/说明/作者/时间。
- 左侧文件树按目录分组，目录默认展开；点击文件加载内容。
- 右侧代码查看器：文件路径面包屑、行号、等宽字体代码内容。
- 默认打开 `README.md`；文件缺失时展示空状态。
- 分支切换更新当前分支与提交栏显示；演示文件内容为静态快照。
- 六个仓库均有演示文件集：
  - Go 仓库：README、go.mod、cmd/server/main.go、internal 业务文件、配置、Dockerfile。
  - React 仓库：README、package.json、vite.config.ts、src 入口与页面文件、Dockerfile。
  - Python 仓库：README、pyproject.toml、app 入口与 RAG 文件、测试、Dockerfile。
- 窄屏下文件树和代码查看器上下堆叠。

### 4.3 合并请求 Tab

- 只展示当前仓库的 MR。
- 表格列：合并请求、作者、源/目标分支、检查、状态、更新。
- 点击行进入 MR 详情页；支持键盘操作。
- 无 MR 时展示空状态。
- 不提供新建 MR 入口。

### 4.4 配置 Tab

- 表单字段：仓库名称、仓库描述、默认分支、可见性。
- 仓库名称必填；默认分支必须属于仓库分支列表；可见性为私有 / 公开。
- 保存后更新仓库详情头部和代码仓列表，写入审计并提示。
- 仓库名称变更时同步更新仓库路径为 `platform/<新名称>`。
- 不提供归档、删除或转移仓库。

## 5. MR 详情

采用单栏布局，从上到下：

1. **头部**：返回合并请求、MR 标题、状态、编号、作者、更新时间、源/目标分支、变更文件数、+/− 统计。
2. **操作**：待评审 / 待审批状态显示「批准 MR」；批准后状态与 review 检查更新。
3. **变更说明**：MR description。
4. **关联需求**：展示需求编号、标题、状态、责任人；可点击打开需求详情抽屉；未关联时显示「未关联需求」。
5. **流水线结果**：build / test / scan / review 四项检查及状态。
6. **讨论区**：
   - 普通评论：作者、时间、正文。
   - 代码评审评论：作者、时间、文件路径与行号、代码片段、评审意见。
   - 底部普通评论输入框与「发表评论」按钮；空评论不可提交；新增评论写入内存并展示，写审计。
   - 评审评论为预置数据，不支持在页面上新增。

## 6. 数据模型与演示数据

### 6.1 仓库

在现有 `REPOS` 上增加：

- `description`：仓库描述。
- `visibility`：私有 / 公开。

仓库详情数据按 `repoId` 维护：

- `branches`：分支列表。
- `files`：`{ path, content }` 列表。

演示仓库：

| 仓库 | 描述 | 可见性 | 主要分支 |
| --- | --- | --- | --- |
| order-api | 订单履约核心 API | 私有 | main、feat/order-timeout、fix/export-timeout |
| order-web | 订单履约运营前端 | 公开 | main、feat/mobile-dashboard |
| order-worker | 履约任务与状态机 Worker | 私有 | main、fix/state-machine |
| order-admin | 订单中心后台管理 | 私有 | main |
| customer-portal | 客户运营门户 | 公开 | main、fix/health-check |
| support-bot | 客服知识库与问答机器人 | 私有 | main、feat/kb-search |

### 6.2 合并请求

在现有 `MRS` 上增加：

- `description`：变更说明。
- `requirementId`：关联需求编号，可为空。
- `comments`：评论数组，评论结构：
  - `id`
  - `author`
  - `time`
  - `kind`：`comment` 或 `review`
  - `content`
  - review 评论额外包含 `file`、`line`、`code`

演示数据：

| MR | 标题 | 关联需求 | 说明 |
| --- | --- | --- | --- |
| !128 | feat: 订单履约超时预警 | RQ-101 | 新增阈值读取与超时预警，补充单测 |
| !127 | feat: 履约看板移动端适配 | RQ-103 | 增加移动端布局与指标卡 |
| !126 | fix: state machine transition | RQ-111 | 修复已支付未拣货订单错误推进状态 |
| !129 | fix: health check timeout | 未关联 | 延长健康检查超时，修复探针偶发失败 |

- !128 预置至少 2 条代码评审评论，分别引用 `internal/fulfillment/timeout.go` 的代码行；并预置普通评论。
- !127、!126、!129 各预置至少 1 条评论，其中 !127 含代码评审评论。

## 7. 页面状态与交互

- 新增详情状态：当前仓库 Tab（代码 / 合并请求 / 配置）、当前文件路径、当前分支。
- 打开仓库详情时默认：代码 Tab、README.md、仓库默认分支。
- 打开 MR 详情时记录返回目标为仓库合并请求 Tab。
- 代码文件切换、分支切换、Tab 切换均重新渲染详情内容。
- 配置保存后重新渲染详情头部，并同步仓库列表数据；仓库名称变更时同步路径为 `platform/<新名称>`。
- 新增普通评论后重新渲染讨论区，并滚动到讨论区底部。
- 空评论不可提交；仓库不存在或 MR 不属于当前仓库时展示「未找到」并提供返回链接。

---

## 8. 兼容与影响范围

- 知识库页面保持不变。
- 代码仓外层移除合并请求 Tab 与 `codeTab` 状态。
- 原 MR 抽屉不再用于代码仓流程；批准 MR 逻辑继续复用。
- 现有侧栏「代码仓」入口保持，代码仓详情与 MR 详情均保持该入口高亮。
- 现有测试需更新代码仓外层断言，并新增仓库详情与 MR 详情测试。

---

## 9. 测试与验收标准

1. `#/code` 为纯仓库列表，无 Tab；点击仓库卡进入 `#/code/<repoId>`。
2. 仓库详情保留侧栏，代码仓高亮，返回链接可回到列表。
3. 代码 Tab 展示分支、最新提交、文件树与默认 README；点击文件后代码内容更新。
4. 分支下拉框可切换并更新当前分支显示。
5. 合并请求 Tab 只展示当前仓库 MR；点击 MR 进入独立详情页。
6. MR 详情包含标题、说明、关联需求、流水线结果、讨论区；评审评论展示文件/行号/代码片段。
7. 待评审 MR 可批准，批准后状态更新；返回仓库 PR Tab 可看到新状态。
8. 普通评论可新增并展示，写审计。
9. 配置 Tab 可修改名称、描述、默认分支、可见性；保存后详情头部与仓库列表同步更新。
10. 直接访问仓库详情与 MR 详情路由时项目上下文正确。
11. 无控制台报错，现有需求、任务、团队、知识库功能不回归。
