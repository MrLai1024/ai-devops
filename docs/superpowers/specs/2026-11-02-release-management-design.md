# 发布管理（发布排期）设计方案

> 版本：v0.1（评审稿）
> 日期：2026-11-02
> 状态：待评审
> 范围：需求管理 → 发布管理 Tab 改造；不改变侧栏批次发布执行流程
> 关联：[AI DevOps 平台总体设计方案](2026-10-23-ai-devops-platform-design.md)

---

## 1. 背景与目标

### 1.1 背景

需求管理下的第三个 Tab 当前为「发布计划」，展示发布就绪检查和单一进行中的批次发布。用户希望将其更名为「发布管理」，从单一发布门禁视图升级为可维护多个发布排期的管理列表。

现有「批次发布」页面负责发布执行、审批、失败重试与回滚；本次改造只覆盖需求管理内的发布排期管理，不改变批次发布执行流程。

### 1.2 目标

1. 将「发布计划」Tab 更名为「发布管理」。
2. 用发布列表替换原有的就绪检查与本次发布范围卡片。
3. 支持新建发布，每个发布包含名称、时间段和关联需求。
4. 发布状态按时间段自动推导，无需手工流转。
5. 提供发布详情，展示完整时间段与关联需求。

### 1.3 非目标

- 不触发、不编辑现有的批次发布执行流程。
- 不引入发布审批流、应用/digest 选择、失败重试或回滚。
- 不支持编辑或删除已创建的发布。
- 不校验发布时间段是否重叠，也不校验时间段是否落在迭代起止日期内。
- 不支持跨迭代关联需求。

## 2. 数据模型与规则

### 2.1 发布实体

新增按迭代归属的发布列表：

| 字段 | 说明 |
| --- | --- |
| `id` | 发布编号，从 `REL-104` 起递增 |
| `name` | 发布名称 |
| `iterationId` / `projectId` | 所属迭代与项目 |
| `startAt` / `endAt` | 时间段，格式 `YYYY-MM-DDTHH:mm` |
| `requirementIds` | 关联需求编号列表 |
| `createdBy` | 创建人，当前演示用户为张明 |
| `createdAt` | 创建时间 |

预置演示数据见第 5 节。

### 2.2 状态推导

为与现有演示数据（2026-10-24 前后的迭代与发布记录）保持一致，使用固定演示时间 **2026-10-24 10:30** 作为状态判断基准，而不是真实系统时间。

| 条件 | 状态 |
| --- | --- |
| 演示时间 < `startAt` | 未开始 |
| `startAt` ≤ 演示时间 ≤ `endAt` | 进行中 |
| 演示时间 > `endAt` | 已结束 |

状态只读，不提供手动切换。

### 2.3 关联需求

- 可选范围：当前迭代内 `deferredTo` 为空的需求。
- 不限制需求状态；分析、设计、开发、测试、发布状态均可提前纳入发布排期。
- 每个发布至少关联一个需求。
- 同一需求可出现在多个发布中。
- 发布名称允许重复。
- 发布创建后，如关联需求被延期，发布仍保留该关联；详情中展示「已延期」标记。

### 2.4 排序规则

默认按状态优先级排序：进行中 → 未开始 → 已结束；同状态按 `startAt` 升序。

## 3. 页面设计

### 3.1 Tab 与列表

- Tab 文案由「发布计划」改为「发布管理」，内部仍沿用 `plan` 标识，减少对现有路由与状态的改动。
- 移除原「发布就绪检查」和「本次发布范围」卡片。
- 列表只展示当前迭代的发布，切换迭代后同步切换。
- 列表头部展示：发布管理标题、当前迭代与发布数量、右上角「新建发布」按钮。
- 表格列：

| 列 | 内容 |
| --- | --- |
| 发布名称 | 名称 + 发布编号 |
| 时间段 | 紧凑格式，如 `10-24 20:00 → 10-24 23:00` |
| 状态 | 未开始 / 进行中 / 已结束 |
| 关联需求 | 数量 + 前两个需求编号，超出显示 `+N` |
| 创建人 | 创建人姓名 |
| 操作 | 「查看」打开详情抽屉 |

- 整行可点击打开详情。
- 状态颜色：进行中绿色、未开始蓝色、已结束灰色。
- 无发布时展示空状态，并提供新建发布入口。

### 3.2 新建发布弹窗

采用现有 modal 抽屉样式，表单字段：

1. **发布名称**：文本，必填，最大 60 字。
2. **时间段**：开始时间、结束时间两个 `datetime-local` 输入；默认 `2026-10-24 20:00` 至 `2026-10-24 23:00`。
3. **关联需求**：可滚动多选清单，展示需求编号、标题、状态、责任人；已延期需求不展示。

校验规则：

- 名称不能为空。
- 开始、结束时间必填。
- 结束时间必须晚于开始时间。
- 至少选择一个关联需求。
- 当前迭代没有可选需求时，展示提示，且不允许提交。

提交后：

- 生成 `REL-xxx` 编号，创建人记为张明，创建时间固定为演示时间 `2026-10-24 10:30`。
- 追加到发布列表并关闭弹窗。
- 提示创建成功及推导出的发布状态。
- 写入审计日志。

表单底部提示：发布状态按时间段自动推导；发布管理仅用于排期，实际执行请前往批次发布。

### 3.3 发布详情抽屉

- 标题：发布名称；副标题：发布编号 + 所属迭代。
- 展示状态、完整时间段、创建人、创建时间。
- 关联需求列表：编号、标题、状态、优先级、责任人；已延期需求附加「已延期」标记。
- 提示文案：发布管理仅用于排期，实际发布执行请在「批次发布」中完成。
- 使用右上角关闭按钮，不设置底部操作区。

## 4. 兼容与影响范围

- 侧栏「批次发布」页面、`state.release` 及现有发布演练逻辑保持不变。
- 原发布门禁入口在需求管理 Tab 内移除；批次发布页面中的发布门禁入口继续保留。
- 需求管理的「需求列表」「任务看板」Tab 不受影响。
- README 中的信息架构与演示路径同步更新。

## 6. 测试与验收标准

1. 需求管理第三个 Tab 文案为「发布管理」，原发布就绪检查内容不再出现。
2. 列表展示 3 条预置发布，时间段、关联需求数量与创建人正确。
3. 三条预置发布分别显示进行中、未开始、已结束。
4. 新建发布弹窗包含名称、开始/结束时间、关联需求多选。
5. 已延期需求不出现在可选清单中。
6. 空名称、结束时间不晚于开始时间、未选择需求时无法提交。
7. 成功创建后列表新增一行，状态按时间段正确推导。
8. 点击发布行或「查看」可打开详情抽屉，展示完整时间段与关联需求。
9. 批次发布页面保持原有行为，无控制台报错。
